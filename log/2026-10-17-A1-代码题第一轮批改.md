**T1 的四处偏差**（对照 `code.md` 的规格表）：

1. `__init__(self, value)` 没有默认值 → `Counter()` 报缺参数；规格是 `start=0`
2. `__call__(self, x=None)` 收下 `x` 却不用 → `c(5)` 应得 6，实际得 2。**规格是"当前值加上 step"**
3. `__len__` 里 `self.step += 1` → 违反"`len` 不改任何状态"
4. 用 `self.step` 存调用次数 → 名字（step）与含义（calls）错位

这四条里第 2 条是**设计问题不是笔误**，所以要求重写而不是打补丁。

**T6 第 3 处按下不表**：那段 `forward` 里 `@` 与逐元素乘法的区别是 B03 的内容，

T1 的实测（这是他这轮"改"之后的行为）：

```
c()      = 0      # 期望 1
c(5)     = 1      # 期望 6
len(c)   = 2      # 对
repr(c)  = Counter(value=0, calls=2)
Counter(start=10)() = 10   # 期望 11
```

`step` 仍然只是被用来数调用次数：`def __call__(self, step=1): self.step += 1; return self.start + self.step - 1`。
把 `self.step` 改名成 `calls`、把 `__len__` 的自增去掉，都只是表面修正——
**核心语义（"把这次的 step 加到当前值上"）没动，而且现在连 `self.value` 这个属性都不存在了。**
这一题需要按规格重写，不是在现有表达式上继续调。

| T1 | 仍不通过 | 见下 |

T1 第二次改后的实测：

```
c()     = 0   # 期望 1
c(5)    = 5   # 期望 6
len(c)  = 0   # 期望 2
repr    = Counter(value=6, calls=0)
Counter(start=10)() = 10   # 期望 11
```

现在的 `__call__` 是 `self.start += step; return self.start + self.step - 1`。
`self.start` 承担了"当前值"的职责（这一步对了），但返回值多加了一个 `self.step - 1`，
而 `self.step` **从头到尾没有自增过**，恒为 0，于是每次返回都少 1；`calls` 也永远是 0。
**修的是一处表达式，不是结构**——离通过只差这一处，且不需要再加属性。

同时修了 `tools/check_a1.py` 的 T1 断言：原来的失败信息写成 `f"...得到 {c()!r}"`，
报错时会**再调用一次** `c()`（有副作用），印出来的数字是第二次调用的结果，
指向错误的方向。改成先调用、把结果存进变量再断言。
